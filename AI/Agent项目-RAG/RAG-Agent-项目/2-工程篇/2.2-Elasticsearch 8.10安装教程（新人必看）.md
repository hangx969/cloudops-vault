在 macOS 上使用 Homebrew 安装 Elasticsearch 时，可能会遇到 No available formula with the name "elasticsearch" 的错误。这是因为从 Elasticsearch 8.x 开始，官方不再通过 Homebrew 提供安装包。



1. 安装 ES

步骤 1：下载 Elasticsearch

访问 Elasticsearch

![](https://raw.githubusercontent.com/hangx969/upload-images-md/main/20260501223424256.png)

Windows 系统下载第一个版本，Apple 芯片的 macOS 下载第三个版本，英特尔芯片的 macOS 下载第二个版本。

![](https://raw.githubusercontent.com/hangx969/upload-images-md/main/20260501223426698.png)

也可以通过 curl 下载 8.10.0 版本：

```ruby
curl -O https://artifacts.elastic.co/downloads/elasticsearch/elasticsearch-8.10.0-darwin-x86_64.tar.gz  
复制代码
```

### 步骤 2：解压文件

直接解压下载的文件即可。

![](https://raw.githubusercontent.com/hangx969/upload-images-md/main/20260501223428838.png)

也可以通过 tar 命令。

```bash
tar -xzf elasticsearch-8.10.0-darwin-x86_64.tar.gz  
cd elasticsearch-8.10.0  
复制代码
```

### 步骤 3：启动 Elasticsearch

可以直接进入到 bin 目录，然后执行 `./elasticsearch` 启动 ES。

![](https://raw.githubusercontent.com/hangx969/upload-images-md/main/20260501223431522.png)

默认情况下，ES 会自动配置堆大小，不会设置固定的内存上限，因此会根据系统可用内存自动分配。我本机上的 ES 有时会占用 30 多个 G 的内存。如果你的机器没有这么大的内存空间，可以运行下面的命令：

```plaintext
ES_JAVA_OPTS="-Xms5g -Xmx5g" ./bin/elasticsearch
复制代码
```

-Xms 设置初始堆大小，-Xmx 设置最大堆大小，建议将 -Xms 和 -Xmx 设置为相同值，避免堆动态调整的开销。

![](https://raw.githubusercontent.com/hangx969/upload-images-md/main/20260501223434994.png)

ES 8.10.0 需要 JDK 17，运行 ES 前建议先配置好 JDK 17。

可以通过这个链接查看版本对应关系： [<u>https://www.elastic.co/cn/support/matrix#matrix_jvm</u>](https://www.elastic.co/cn/support/matrix#matrix_jvm)

![](https://raw.githubusercontent.com/hangx969/upload-images-md/main/20260501223438448.png)

也可以直接在上一级目录执行下面的命令启动。

```bash
./bin/elasticsearch 
复制代码
```

默认情况下，Elasticsearch 会在前台运行，并监听 9200 端口。ES 从 8.x 版本开始启用安全功能，因此会显示以下输出，记得保存。

![](https://raw.githubusercontent.com/hangx969/upload-images-md/main/20260501223441250.png)

如果 ES 没有加载预期的 JDK 版本，可以这样启动：

```plaintext
ES_JAVA_HOME=$JAVA_HOME ./bin/elasticsearch -d
复制代码
```

![](https://raw.githubusercontent.com/hangx969/upload-images-md/main/20260501223443943.png)

### Linux 服务器后台运行

如果你希望 Elasticsearch 在后台运行，可以使用 **nohup**：

```bash
nohup ./bin/elasticsearch > elasticsearch.log 2>&1  
```

## ES安全功能解除方法

ES 的安全功能包括：

1. **HTTPS**：所有通信默认使用 HTTPS。

2. **身份验证**：需要用户名和密码才能访问 Elasticsearch。

3) **证书生成**：安装时会自动生成 TLS/SSL 证书。

Elasticsearch 默认启用 HTTPS（加密通信）。如果尝试通过 HTTP（明文通信）访问，就会出现以下错误：

```plaintext
received plaintext http traffic on an https channel, closing connection  
复制代码
```

这表明你的客户端（如 curl 或浏览器）发送的是 HTTP 请求，而 Elasticsearch 配置为仅接受 HTTPS 请求

### 方法 1：使用 HTTPS 访问 Elasticsearch

默认情况下，Elasticsearch 会在安装目录下生成一个自签名证书，并启用 HTTPS。你可以通过以下步骤使用 HTTPS 访问 Elasticsearch。

#### 步骤 1：找到生成的证书

在安装 Elasticsearch 时，系统会提示你保存以下信息：

**①、CA 证书路径**：通常位于 `elasticsearch-8.10.0/config/certs/http_ca.crt` 。

![](https://raw.githubusercontent.com/hangx969/upload-images-md/main/20260501223447484.png)

**②、 用户名和密码**：默认用户是 elastic，密码会在启动时生成。

![](https://raw.githubusercontent.com/hangx969/upload-images-md/main/20260501223449951.png)

如果忘记了密码，可以通过以下命令重置：

```bash
./bin/elasticsearch-reset-password -u elastic
```

#### 步骤 2：使用 HTTPS 访问

回到解压目录（注意不是 bin 目录），运行以下命令，指定 CA 证书并使用 HTTPS 协议：

```bash
curl --cacert config/certs/http_ca.crt -X GET "https://localhost:9200" -u elast
```

系统会提示输入密码。输入 elastic 用户的密码后即可访问。

![](https://raw.githubusercontent.com/hangx969/upload-images-md/main/20260501223452910.png)

注意⚠️，记得将 ES 密码配置到本地代码的 application.yml 文件中，并确保与 ES 生成的密码一致。

![](https://raw.githubusercontent.com/hangx969/upload-images-md/main/20260501223455686.png)

### ~~方法 2：禁用 HTTPS 和安全功能（仅限本地测试环境）~~

如果只是在本地开发环境中使用 Elasticsearch，也可以禁用 HTTPS 和身份验证。

#### 步骤 1：修改配置文件

编辑 config/elasticsearch.yml 文件，把这两个配置项修改为 false。

![](https://raw.githubusercontent.com/hangx969/upload-images-md/main/20260501223458762.png)

修改对应的内容为：

```yaml
xpack.security.enabled: false  
xpack.security.http.ssl.enabled: false 
复制代码
```

#### 步骤 2：重启 Elasticsearch

重新启动 Elasticsearch：

```bash
./bin/elasticsearch  
```

![](https://raw.githubusercontent.com/hangx969/upload-images-md/main/20260501223501463.png)

#### 步骤 3：使用 HTTP 访问

现在可以通过 HTTP 协议访问 Elasticsearch：

```sql
curl -X GET "http://localhost:9200"  
复制代码
```

![](https://raw.githubusercontent.com/hangx969/upload-images-md/main/20260501223504710.png)

#### 注意事项

* 禁用安全功能仅适用于开发环境，生产环境中不建议这样做。

* 如果你在 Docker 中运行 Elasticsearch，请确保将 xpack.security.enabled 设置为 false。

这时候，还要确保 application.yml 中的 ES 用的是 HTTP 请求。

![](https://raw.githubusercontent.com/hangx969/upload-images-md/main/20260501223507662.png)

否则会在启动后端的时候报错 初始化索引失败。

![](https://raw.githubusercontent.com/hangx969/upload-images-md/main/20260501223510816.png)

## ES 安装 IK 分词器插件

IK 分词器是阿里开源的一个中文分词工具，主要用于全文检索和文本分析。据说最初是由林良益开发的，是 Lucene 和 Elasticsearch 中最常用的中文分词插件之一： [<u>https://github.com/infinilabs/analysis-ik</u>](https://github.com/infinilabs/analysis-ik)

![](https://raw.githubusercontent.com/hangx969/upload-images-md/main/20260501223513788.png)

我查了一下，发现这个项目早在 2012 年就已经出现。当时 ITEYE 上还有一篇博文介绍；看头像就像是远古时期的程序员大佬。

![](https://raw.githubusercontent.com/hangx969/upload-images-md/main/20260501223516884.png)

死去的记忆又开始攻击我了，哈哈哈。我在 2015 年之前也活跃过这里。

![](https://raw.githubusercontent.com/hangx969/upload-images-md/main/20260501223519901.png)

传统分词工具往往难以准确处理中文歧义和复杂语境，而 IK 分词器可以识别中文词组、处理专有名词，并智能切分复杂句子。

![](https://raw.githubusercontent.com/hangx969/upload-images-md/main/20260501223522620.png)

历小冰：IK 分词器

### 为什么要安装 IK 分词器呢？

Elasticsearch 默认的分词器（如 standard analyzer）针对英文等西方语言设计，对中文文本处理效果极其有限。这主要是因为英文单词之间有空格，而中文是连续书写的，没有自然分词的边界，标准的分词器会逐字切分，导致语义完全丢失。

比如说 程序员爱编程，默认的分词器会分割为 程 | 序 | 员 | 爱 | 编 | 程，IK 分词器能够切分为 程序员｜爱｜编程。

IK分词器提供了两种主要分词模式：ik\_max\_word，最细粒度的分词模式，会穷尽所有可能的分词组合，适合全文检索；ik\_smart，智能分词模式，最少分词，尽可能保留语义完整的词组，适合精准匹配。

#### <u>下载并安装插件</u>

IK 分词插件的 [<u>GitHub 主页 </u>](https://github.com/infinilabs/analysis-ik?tab=readme-ov-file)里有提供插件的安装方式。

![](https://raw.githubusercontent.com/hangx969/upload-images-md/main/20260501223525382.png)

可以通过命令行直接安装，macOS 的执行命令如下所示：

```bash
./bin/elasticsearch-plugin install https://get.infini.cloud/elasticsearch/analysis-ik/8.10.0.zip 
复制代码
```

但很遗憾，我这里执行失败了。

![](https://raw.githubusercontent.com/hangx969/upload-images-md/main/20260501223528380.png)

问了一嘴 Claude，说可以用 `./bin/elasticsearch-plugin install` `https://github.com/medcl/elasticsearch-analysis-ik/releases/download/v` `版本号/elasticsearch-analysis-ik-版本号.zip` 这个，我没有尝试，大家可以试一下。

那我们就换一种安装方式，先通过这个连接找到匹配的 IK 分词插件连接：

[<u>http://cdn-us-west-release.infinilabs.com/analysis-ik/stable/</u>](http://cdn-us-west-release.infinilabs.com/analysis-ik/stable/)

比如说 8.10 选这个：

![](https://raw.githubusercontent.com/hangx969/upload-images-md/main/20260501223531453.png)

直接点击链接，下载到本地。再使用以下命令安装本地插件：

```bash
./bin/elasticsearch-plugin install file:///Users/itwanger/Downloads/elasticsearch-analysis-ik-8.10.0.zip  
复制代码
```

注意这里的 `/Users/itwanger/Downloads/` 替换成你本地的地址， `file://` 前缀要保留。

![](https://raw.githubusercontent.com/hangx969/upload-images-md/main/20260501223534085.png)

这次安装成功了，安装的过程中会提示 y/n，输入 y 就好了。

![](https://raw.githubusercontent.com/hangx969/upload-images-md/main/20260501223536704.png)

Windows 类似，只需要 `./bin` 的 `./` 删掉就行了。

完成安装后，重启一下 ES。可以运行以下命令验证插件是否安装成功：

```sql
curl -X GET "http://localhost:9200/_cat/plugins?v" 
复制代码
```

输出应包含类似以下内容：

![](https://raw.githubusercontent.com/hangx969/upload-images-md/main/20260501223539628.png)

或者执行 `./bin/elasticsearch-plugin lis`

![](https://raw.githubusercontent.com/hangx969/upload-images-md/main/20260501223542177.png)

表示已经安装成功了。
